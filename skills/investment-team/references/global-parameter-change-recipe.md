# 全局建模参数修改配方（skill 自身的标准变更流程）

> 适用触发：用户要求统一或修改全局建模参数——折现率（WACC）、永续增长率（tg）、评分权重、星级精度、模板默认值等跨多文件的框架级参数。

## 五步流程（2026-11-03 统一 WACC=10%/tg=3% 实战验证：10 处替换一次全过、全程 ~1 分钟）

### 第 1 步：口径盘点（区分「处方」vs「历史叙述」）
grep 扫描整个 skill 目录（SKILL.md + references/ + templates/ + scripts/）找参数所有出现：
- **处方性出现（必须改）**：模板默认值与注释、示例调用骨架中的参数行、敏感性矩阵推荐区间、校准建议句（如"必须手动校准 tg=2.5-3%"）
- **历史案例叙述：分两种模式（2026-11-04 起区分）**
  - **轻量模式（只改 skill 处方）**：历史实战数字不重写，保留原值 + 标注历史口径存档 + 指向新规范（WM 6.5-8%、MTD 7.5-9.5%、REIT 8% 均如此处理）。
  - **全量模式（用户要求全框架统一口径）**：repo `reports/` 下全部公司报告的历史估值数字**同步重算**（2026-11-04 实战：34 家公司 00-05 文件 149 份 + 引擎 + JSON + 变更日志，155 files），按下方「Repo 层全量重算配方」执行——不要拿「历史报告一律不动」的旧规则应付全量模式。

### 第 2 步：先重算演示值，再改文档
文档中内嵌输出数字的代码骨架/示例（如 `dcf-three-scenario-script-usage.md` 东鹏骨架的 IV 81.6/172.8/300.5、零增长锚 81.9）在参数变更后**全部失真**——失真的文档数字比缺失更危险（未来会话会直接引用）。先 import 脚本用新参数实跑一遍，把新数字准备好再动手改文档。

### 第 3 步：批量原子替换（execute_code 单脚本）
全部 old/new 对写进一个脚本，每处断言 `text.count(old) == 1`：1=替换、0 且 new 已在文中=幂等跳过、其他=PROBE 不动文件，逐条回显命中状态。**不逐处 patch**——长中文行 + 行号描述直接 patch 的 old_string 猜不准（同审计批量修复配方）。先跑一遍纯计数探查（不写盘）确认全部命中后再真正替换，避免半套替换。

### 第 4 步：三重验证
1. **语法**：修改过的 .py 全部过 `py_compile`
2. **实跑对拍**：文档中的代码骨架原样实跑，输出必须与新写入文档的数字逐一吻合（本次 85.7/156.0/231.5/75.8 全对上）
3. **残留扫描**：grep 旧口径处方（旧区间/旧默认值如 `tg=2.5-3`、`wacc = 0.08`），确认剩余命中全部是历史叙述

### 第 5 步：镜像 + 推送
copytree 真镜像（`dirs_exist_ok=True` + 删除源中已不存在文件，跳过 `__pycache__`/`.git`）→ `git add skills/investment-team` → commit message 列明改动文件与重算值 → fetch-first 自动 `git pull --rebase` 重试推送（模板 `templates/git-push-report.py`，subprocess 用 list 参数传 commit message，勿手搓 shell 字符串插值）。镜像 diff 里出现往轮遗留未同步文件时顺带补齐（本次带出了 ah-dual-listing-analysis.md）。

## Repo 层全量重算配方（全量模式专用，2026-11-04 WACC10/tg3 34 家轮实战）

> skill 处方改完后，repo 内已有报告的全部派生估值（三/四情景 IV、敏感性矩阵、反向 DCF、DDM、零增长锚、击球区、衍生引用）也要同步重算。引擎：`tools/unified_param_engine.py`（affine 法 IV=a×EV+b，残差吸收股本/汇率差异；RS=results JSON，26 家 affine + 4 家 ratio 法 ab=None）。经验：一次全量轮 155 文件、+2808/-767 行。

1. **先修引擎，再动文档**：统一框架参数必须注入所有模型内部——警惕「情景结构参数」伪装成情景假设。腾讯 eval_scen 的 tencent 分支把 gterm=2.5% 硬编码进情景结构，与统一 tg=3% 冲突；修复注入后 427.4 才是正确基准。逐模型过一遍「框架参数（WACC/tg）vs 情景参数（g1/g2）」的边界。
2. **锚校验必须同源同参**：公式值（a×model@新参+b）只对拍同参数同来源的 RS new 列。不要拿旧参公式对拍新参 RS——首轮就犯了这错，白白排查一轮「忘乘 ab」。
3. **ratio 法公司例外**：RS 中 ab=None（辉瑞/福耀/EQIX/Nu）不适用 affine 法，保持原值；批量重算前先按方法分段。
4. **敏感性矩阵是展示参数不是残留，但格子输出必须重算**：矩阵轴（WACC 8.5-10.5% 等）允许保留展示区间，轴上全部格值随新参数重算写回；明细公司矩阵逐个过锚校验（本轮 8/8 通过才算数）。
5. **不在 RS 的公司用「报告内公式复原法」**：从该公司 00-数据包的首轮公式段重建模型，反标定辅助参数（归创通桥：meidi 模型 + 净现金/股本 → RMB→HKD，汇率 k=1.089 标定至 @新参 输出精确吻合首轮值）后才允许重建情景——复原不吻合就说明形状没锁住，禁止硬编。
6. **反向 DCF 隐含增速用 Δ迁移法**：模型形状复原残差 >3% 时不要硬重建——先用旧参数复现形状并反解旧隐含增速（验证形状，dcf55 类两段模型 @旧参 复现 13.58% ≈ 文档 13.1% 即锁定），再迁移 Δ =（新参形状解 − 旧参形状解）到文档旧值（鼎力 13.1%+0.84pp=13.9%，泉峰 FCF0=75 → 19.0%）。形状锁死门：残差 ≤3% 才可信。
7. **隐含增速 bisect 打满边界 = 假解**：上界 0.30 被打满（卡特现价真实隐含 ~45%，脱离网格）→ 禁止发布边界值当收敛解；改列语义为「中性锚定列」——用 (WACC, g_中性) 的自洽 IV 加粗呈现，原文档旧解回滚保留。
8. **叙述性残留清零，防两类误伤**：①财务数据数字（营收/利润里含同样的 "10%"、"3" 字串）不算残留，只扫叙述语境 token，逐文件计数归类；②衍生语境同步——A 公司隐含增速被其他公司文件引用时（卡特 13.6% 被 ×7 文件引用、海底捞 79 折链 ×6 文件），引用处一起改。替换必须回显命中数：`倍）。` 匹配不上 `倍）**。`（粗体星号吞 old_string）、「凭什么叫/凭什么让」一字之差静默 no-op，都是真实踩过的坑——替换后对新文本跑 PROBE 复核。
9. **网格函数参数防呆**：敏感性轴传 8.5 而非 0.085 会让整张网格塌成常数且不报错——写回文档前检查网格输出存在离散度（min≠max）。
10. **变更日志 + 单 commit 推送**：`reports/{YYYYMM}/{日期}_统一参数变更日志.md` 记录口径定义、覆盖面、关键值迁移表；全部改动（报告+引擎+JSON+日志）与 skill 镜像同一个 commit 推送。
