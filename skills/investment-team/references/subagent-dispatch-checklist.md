# 四大师子报告派发与验收清单（2026-10 海底捞实战沉淀）

主会话派发子报告（delegate_task batch）的派发纪律与验收纪律。SKILL.md 的"五件套 prompt"定义**怎么派**，本清单定义**派完怎么收**。

## 派发

1. **批次结构**：3 并行（段/巴/芒）+ 第 2 批单发（李录）。单批 ≤3 由 max_concurrent_children 决定，勿超。
2. **prompt 必含**：数据包绝对路径 + 禁止外部数据/禁止重算估值 + 输出文件绝对路径 + 参考体例路径 + 预判分锚 ±0.25 授权 + 行数区间 + **明确"不做 git 操作，主会话统一提交"**（子代理自行 commit 会与并行写入冲突）。
3. 各大师分工边界写进 context（海底捞实战："治理红旗归芒格、借钱分红归巴菲特，李录不重复展开"），避免四份报告互抄。

## 验收（每个子报告四道检查）

1. **超时 ≠ 失败**：delegate_task 600s 超时后**先查输出文件是否存在**（行数 + 尾部完整性 + 评分行），再决定是否重派。海底捞芒格代理超时，但文件已完整写出（138 行、评分、Follow-up 齐全）——盲目重派浪费 500s+。检查姿势：`wc -l` + grep 评分/结论/Follow-up + 读尾部 20 行。**补跑 prompt 追加效率指令**（招行 2026-10-20 实战）：超时既可能发生在写盘后（芒格 14 次 API 调用、文件已完整落盘），也可能发生在写盘前（巴菲特 6 次调用、文件未落盘）——只有后者才需重派；重派 prompt 末尾追加「读文件有节制：SKILL.md+数据包+scoring_template 足矣，references 只挑与该大师直接相关的 1-2 个文件；读完数据包后一次性写文件，写完即结束」，补跑 282-414s 全部按时完成（对比首轮 600s 全超时）。
2. **跨报告引用表必须对账**：子代理爱写"系列内已完成报告快照"表，且**会编造数字**（海底捞芒格报告写滨江 3.50，repo 实际 2.75；其余 9 票核对仅 1 处错）。任何子报告里的系列对照表，逐票 grep 各标的相关报告的实际评分核对，错了 patch 修正后再入库。方法：`grep -rn "X.XX / 5" reports/YYYYMM/*/03-*.md` 逐票取数。
3. **评分链一致性**：grep 四份子报告的总评分行（`投资吸引力总评分`/`评分：`），与 05 综合裁决引用值逐一比对；综合分 = 等权平均，两位小数，**舍入用四舍五入 ROUND_HALF_UP**（东鹏 3.625→3.63、台积电 3.375→3.38，与 SKILL.md 评分体系节 3.125→3.13 同规则）——勿用 Python `round()`：银行家舍入会把 3.625 舍成 3.62，破坏与历史报告链的一致性。
4. **价格一致性**：现价字符串（如 9.365）应出现在全部文件中（`grep -c '9.365' 0[0-5]*.md`），综合报告"现价 X 在价格带 Y 内"的位置描述与数字自洽。

## 已验证有效的做法

- 数据包 §10 "口径约定" + §11 "主会话预判锚"两个硬约束，本次四位大师全部维持锚未乱修分——继续保留。**零偏离二次确认（招行 2026-10-20）**：§12 四大师预判锚（段4.00/巴3.75/芒3.25/李3.75）四份子报告全部零偏离——当锚从数据包内模型输出直接推算（金融机构三锚、DCF 加权等）而非凭感觉估时，命中率最高。
- 芒格式风险报告自带"FCF 对股息覆盖率"类包内自算（36.6÷38.9=0.94x）是加分项：用包内数字自算新比率 + 标注"自算"，符合纪律，不算违规。
- 子报告尾部"上修/下修触发器 + Follow-up 问题"结构在综合裁决中直接复用，两处必须呼应（综合裁决的触发器应汇总各子报告版本）。
